# 客服红名单日巡 SOP（Phase 0 / Phase 1）

> 目标：1 人维护约 50 家门店时，**每天只处理红色异常客户**，不逐家进系统检查。

## 1. 入口

平台控制台 → **健康** 页（`/platform-admin`）  
API：`GET /api/admin/health-center/board`

## 2. 每日节奏（建议 30 分钟内完成）

1. 打开健康中心，默认「仅看红色」  
2. 若昨晚未跑全量扫描：点「全量扫描」（生产已在 CST 07:00–07:14 自动扫描）  
3. 按列表从上到下处理红租户（只处理「客服可处理」红项；系统观测项看分流队列「研发」）  
4. 点开每条红项：看责任方、影响模块、FAQ  
5. 处理完标记认知：客户可处理 → 通知客户；第三方 → 记供应商工单；平台 → 升级研发值班  
6. 黄/绿租户当日**不主动打扰**，除非续费风险反馈  
7. 手机号匹配率等结构性观察项为黄灯观察，**不进日巡红名单**（见 `docs/轻服务-红名单误报清单.md`）

## 3. 红绿灯定义

| 灯 | 条件 | 客服动作 |
|----|------|----------|
| 红 | 存在**客服可处理**的 P0/P1，或租户级致命信号（如近 7 日触达失败率过高），或调整后托管风险=高 | **必须当天处理** |
| 黄 | 仅有系统观测 P0/P1、结构性手机号观察、托管风险=中、补充信号警告 | 可顺延，续费周重点看 |
| 绿 | 无上述阻塞 | 不处理 |
| 灰 | 从未检测 | 先跑一次扫描，再归类 |

## 4. 责任分流（不要全进客服，更不要全进研发）

| 责任方 | 典型问题 | 动作 |
|--------|----------|------|
| 租户管理员 / 店长 / 员工 | 未配营业时间、未设管理员、未确认营销规则、未执行任务 | 发整改说明 + FAQ，记客户待办 |
| 我方实施 / 平台 | POS 接入、定时任务、报告生成、AI 不可用 | 客服建平台工单 |
| 系统接口 | 第三方 API / 同步链路 | 查供应商状态，必要时研发 |
| 客户成功 | 续费风险、长期不登录、月报未消费 | 客户经理跟进 |

### Phase 2 分流队列（健康页内）

扫描或点「同步分流队列」后，红项自动进入四队：

| 队列 | 谁处理 | 默认自愈 |
|------|--------|----------|
| 客户可处理 | 门店/租户管理员 | 通知租户管理员 |
| 客服 / 实施 | 客服日巡 | 复检 / 生成整改报告 |
| 第三方 | 客服先查供应商 | 复检；确需代码再升级 |
| 研发值班 | 仅平台技术或手动升级 | 生成报告；禁止把客户配置问题丢进来 |

白名单自愈仅允许：`rerun_inspection` / `generate_report` / `notify_customer`。  
**禁止**对未知动作做自动修复。升级研发必须人工点「升级研发」。

## 5. 禁止事项

- 禁止为「看起来合理」的单店需求当场承诺研发  
- 禁止未看责任方就把所有红项甩给研发群  
- 禁止用逐店登录代替健康中心红名单

## 6. 验收标准

- 异常店可在 30 分钟内扫完并分流  
- 当日红名单清零或全部有下一步责任人  
- 研发群只收「平台技术 / 第三方需代码」类问题
